# 初识AOI
学习一块特定知识前要做的第一件事就是：先认识它~  

## 什么是AOI?
### 定义 
AOI：感兴趣区域（Area of Interest）。其核心思想就是: **不为每个玩家同步整个世界，而是只为每个玩家同步他“感兴趣”的一小片区域内的实体状态**  

### 核心概念
AOI中分两种角色：**观察者** 与 **被观察者**
- 观察者：通常指玩家、客户端、摄像头、AI 实体
- 被观察者：其他玩家、NPC、怪物、子弹、道具等

### 核心思路
获取新旧视野集合，得出此次事件产生的新事件，对此次受影响的观察者发送新事件

>服务器需要为每个观察者维护一个“可见集合”，即它的 AOI 列表。

### 常见AOI区域
常见AOI区域如下:
- 圆形 / 球形：按距离判定，直观，适合大多数游戏；
- 矩形 / 九宫格：按网格划分，实现简单；
- 视锥：FPS 中只同步前方视野；
- 多边形 / 区域：按房间、副本、地图区块划分；
- 混合形状：距离 + 遮挡 + 队伍关系。

### 优势
AOI带来的优势：
- **降低网络带宽**：减少无意义的数据广播；
- **降低服务器CPU使用率**：减少状态计算和封包数量；
- **降低客户端负担**: 减少渲染和逻辑对象数量；
- **降低延迟与卡顿**: 避免全图广播造成的拥塞。
  
# 常见AOI实现方案
## **1.九宫格/网格**
将地图划分为固定大小的格子，实体属于某个格子。观察者的 AOI 通常是自己所在格 + 周围 8 格，即 3×3 九宫格。  

### 优点:
- 实现简单，查询快；
- 适合 2D MMO、SLG、回合制地图；
- 可用哈希表支持无限地图。

### 缺点：
- 格子大小难调：太小则 AOI 内对象少，体验差；太大则同步压力大；
- 玩家分布不均时，热点格子压力大；
- 边界抖动：玩家在格子边界来回移动，导致频繁 Enter/Leave。
>适用场景：频繁更新、视野相近、密度可控；关注热点和格子尺寸

### 基本实现思路
假设给定2000px * 2000px 尺寸的地图，规定格子大小为50px,显然易得全图共分1600个格子。
  
当一位玩家Player位置为**第x行第y列**格子，易得其AOI视野格子如下:
```
[x-1,y-1]   [x-1,y]    [x-1, y+1]
[x,y-1]     [x,y]      [x,y+1]
[x+1,y-1]   [x+1,y]    [x+1,y+1]
```
取**当前视野**命名为 **View_A**;
  
当玩家移动到**第N行第M列**格子时，根据上面规则获取新视野并命名为**View_B**
  
对**新旧视野取差集/交集**可得此次移动事件中受影响的实例和事件  
如：对Player而言:
- View_A - View_B = 离开player视野的实例/player消失在他们的视野中——Leave事件
- View_B - View_A = 进入player视野的实例/player进入他们的视野——Entry事件
- View_A ∩ View_B = player在它们视野内发送位置移动——Move事件

>若各个实体视野半径相等，则可以用此次AOI事件发生者的新旧视野集合找到此次所有受影响的实例，但是如果各个实体视野半径不相等则需要根据其他方法找出受影响的其他实例
#### 常用格子存储方法
```cpp
//二维存储
//列索引->该索引列中的所有格子/行索引->该索引行中的所有格子
std::unordered_map<int,std::vector<Cell>> cells_;

//一维存储
std::vector<Cell> cells_;
//规定格子索引按下列格式列出
/**
  0   1  2  3  4  5.... 39
  40 41  ....           79
  .   .                  .
  .     ..               .
  .        ...           .
 1560           ....     1599
*/

// 假定当前位置为(x,y)，可按 index = row * cols_ + col 找到对应格子索引
//例如
// 1. 转成相对 AOI 左上角的坐标
int64_t relX = x - minX_;
int64_t relY = y - minY_;

// 2. 算出列、行
uint32_t col = relX / cellSize_;
uint32_t row = relY / cellSize_;

// 3. 转成一维数组下标
uint32_t cell = row * cols_ + col;
```


## **2.十字链表**
### 基本实现思路
服务器中维护两张不同轴的双向链表，表中按实例对应轴上的投影进行排序。
>适用场景: 连续小幅移动、轴范围有筛选力；瞬移会跨过大量节点。

例子:  
当A有移动请求到达时:  
- 1.先按照如下方法寻找A旧位置的视野集合
    - 先在x轴链表双向寻找满足 **实例的x坐标 <= A.x + A.ViewRange | 实例的x坐标 >= A.x - A.ViewRange** 的所有实例并记为OldView_x_set;
    - 然后在y轴链表上双向寻找满足**实例的y坐标 <= A.y + A.ViewRange | 实例的y坐标 >= A.y - A.ViewRange** 的所有实例并记为OldView_y_set;
    - 最后**A旧位置视野集合 OldViewSet = OldView_x_set ∩ OldView_y_set**;
  
- 2.得到两个旧视野集合后,校验并执行A的移动后更新A的坐标和A在两张表中的的位置  
- 3.按照求旧位置视野集合的方法求取新位置的视野集合NewViewSet
- 4.易得
    - OldViewSet - NewViewSet = 离开player视野的实例/player消失在他们的视野中——Leave事件
    - NewViewSet - OldViewSet = 进入player视野的实例/player进入他们的视野——Entry事件
    - OldViewSet ∩ NewViewSet = player在它们视野内发送位置移动——Move事件
